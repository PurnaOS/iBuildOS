# ADR-0013 — Agent state lives in repo artifacts

## Decision

The agent control plane stores everything in the bundle: `Agent` extends
`Actor` (so the existing `assignee` relationship accepts agents polymorphically
— no engine change), and `AgentRun` is modeled on `TestResult` (a
machine-written result record that draws no chain findings). AgentRun ids use
`ARUN-<slug>` because `RUN-<slug>` already belongs to Runbook. The prototype's
PROGRESS.md and TIME_TRACKING.md are rejected as hand-maintained duplicate
state: who-is-working, event log, and heartbeats are all derived from
artifacts and git history. `iBuild run` and `/run-backlog` are operator modes
that commit locally per task (the audit ledger) and can never push; the
knowledge layer (skills, Studio assist) stays suggest-only per AG-003.

## Context

Introduced by CHANGE-agent-control-plane (2026-07-03) for AG-009..AG-012 —
a Paperclip-style control plane where the repo, not a server database, is the
source of truth.
