# DC-0002 — Insights domain wire-contract shape

## Decision

Four judgment calls made filling in `apps/desktop`'s insights domain
(SPEC.md area IN, TM-004, TM-009), where SPEC/FORMATS/DESIGN-CHARTER left the
point open, per the EXECUTION-PLAN.md Builder Charter (rule 1):

1. **Every `insights.*` request takes a required `projectId`,** unlike
   `attention.list`'s optional one. DESIGN-CHARTER §2's nav map has no
   cross-project Insights screen — "Insights" only exists inside a Project
   window's sidebar — so there is no caller that would ever omit it. Optional
   would just move a null-check into every handler for no caller benefit.
2. **TM-004's "my queue" is scoped per-project, not global,** for the same
   reason: the only screen that renders it lives inside one project's window.
   TM-004's spec text ("each user shall have a personal queue") reads
   cross-project in isolation; a real cross-project queue is a plausible
   future screen (a Home-level surface, which doesn't exist yet) and this
   decision should be revisited if/when one is built.
3. **No subscription channels for the insights domain** — every slice is a
   plain request/response query, refetched by the renderer (react-query,
   `my-queue` on a 6s interval matching the backend's own scripted drift)
   rather than pushed live like `activity.events`. Dashboards are read
   on-demand; a push channel would add a second live-update mechanism for
   surfaces where a refetch is indistinguishable to the user.
4. **The insights domain's wire-contract types (zod schemas + inferred TS
   types) live in `shared/ipc/contract/insights.ts`**, not
   `shared/domain.ts` where the "core" domain's equivalents
   (`Project`, `ActivityEvent`, …) live. This work package's boundary list
   didn't include `domain.ts` as editable (kept clear for other work this
   round), so `contract/insights.ts` is this domain's single source of truth
   for its shapes instead; `main/backend/insights.ts` imports the types
   (type-only, no runtime zod dependency crosses the boundary) rather than
   redeclaring structurally-identical interfaces by hand.

Also worth recording as a mechanical note, not a design decision: this work
package's branch started stale (`worktree-agent-ae912ff35a8b0fdc0` was still
on `7daa296`, before the Wave 2 base commit that split `backend.ts`/
`contract.ts` into the per-domain shape this task assumed already existed)
and was fast-forwarded to `main` (`68c5806`) before any of the above.
